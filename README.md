# FaizApp

> Digital platform for managing, controlling and analyzing field operations.

FaizApp — внутренняя цифровая платформа для управления и контроля работы торговых представителей и мерчендайзеров.

Проект создаётся на базе реальных рабочих процессов дистрибьюторской компании и предназначен для автоматизации ежедневного учёта полевой работы: фотоотчётов, мерчендайзинга, планов, результатов, замечаний и статистики.

На первом этапе FaizApp работает как Telegram-бот. В дальнейшем проект может развиваться в полноценную платформу с личным кабинетом, аналитикой, аудитом торговых точек, планограммами и AI-анализом фотографий.

---

## Основные цели

FaizApp создаётся для решения нескольких основных задач:

- автоматизация учёта работы торговых представителей;
- автоматизация подсчёта выполненных мерчей;
- контроль выполнения индивидуальных планов;
- фиксация нарушений и замечаний;
- исключение повторной загрузки одних и тех же фотографий;
- автоматические напоминания сотрудникам;
- формирование ежедневной и месячной статистики;
- снижение объёма ручной работы диспетчера;
- постепенный переход от ручной проверки к автоматизированному анализу.

Главный принцип проекта:

> Система должна автоматизировать подсчёт и рутинную работу, но не заменять человека там, где требуется визуальная оценка.

# Текущий этап

## Этап 1 — пилотный запуск

Первый этап рассчитан на работу в одной Telegram-группе.

В группе находятся:

- торговые представители / мерчендайзеры;
- руководство;
- диспетчер.

На данном этапе бот не принимает самостоятельные решения о качестве мерчендайзинга.

Диспетчер самостоятельно просматривает фотографии и сообщает боту результат проверки.

### Результат проверки

Для каждой работы используется один из трёх вариантов:

- ✅ — принято;
- ⚠️ — принято, но есть замечание;
- ❌ — не принято.

При этом:

- принятое выполнение засчитывается;
- принятое с замечанием засчитывается, но увеличивает счётчик комментариев;
- отклонённое выполнение не засчитывается;
- отклонённое выполнение увеличивает счётчик комментариев и отдельно учитывается как отклонение.

Если работа отклонена, бот должен уведомить соответствующего сотрудника, чтобы он понимал причину расхождения между отправленным отчётом и фактически засчитанным результатом.

# Работа с фотографиями

На первом этапе фотографии проверяются человеком.

Бот отвечает за техническую часть:

- получение фотографий;
- определение отправителя;
- сохранение информации о фотографии;
- предотвращение повторного учёта;
- подсчёт выполнений;
- связь фотографии с результатом проверки;
- фиксацию комментариев.

Для обнаружения повторных фотографий планируется использовать:

- SHA-256 хэш файла;
- доступные метаданные изображения;
- дату и время съёмки, если они присутствуют в EXIF.

GPS и геолокация на первом этапе не используются.

Отсутствие EXIF само по себе не является доказательством того, что фотография старая или повторно использованная.

# Пользователи

На первом этапе используется простая система ролей.

### Торговый представитель / мерчендайзер

Может:

- отправлять фотоотчёты;
- проходить регистрацию;
- получать информацию о результатах;
- получать уведомления и напоминания.

### Диспетчер

Имеет расширенные возможности:

- контроль результатов;
- фиксация принятия или отклонения;
- добавление замечаний;
- просмотр статистики;
- запуск административных команд.

Административные команды не должны быть доступны обычным пользователям.

---

# Регистрация

Регистрация пользователя выполняется через Telegram.

Пользователь отправляет свой Telegram-контакт.

Система сохраняет необходимые данные пользователя в PostgreSQL и связывает Telegram-пользователя с внутренней записью сотрудника.

---

# Планы

Для каждого торгового представителя существует индивидуальный план.

План может иметь:

- дневное значение;
- месячное значение.

План руководителя группы рассчитывается как сумма планов его торговых представителей.

Отдельный личный план руководителя на первом этапе не предусматривается.

---

# Автоматические задачи
FaizApp выполняет регулярные проверки в течение рабочего дня.

Планируемое расписание:

| Время | Действие |
|---|---|
| 10:30 | Проверка выполнения |
| 12:00 | Проверка выполнения |
| 15:00 | Проверка выполнения |
| 16:00 | Итоги рабочего дня |

В течение дня бот проверяет выполнение планов и при необходимости отправляет напоминания.

В 16:00 формируется итоговая статистика.

---

# Ежедневный отчёт

Для диспетчера формируется текстовый отчёт, содержащий информацию о:

- выполненных мерчах;
- сотрудниках;
- выполнении планов;
- опозданиях;
- количестве комментариев;
- количестве отклонений.

Для руководства на первом этапе дополнительно подготавливаются данные, которые используются для формирования Excel-отчёта.

---

# Месячная статистика

Планируется формирование месячной статистики:

- выполнение плана;
- невыполнение плана;
- лучшие сотрудники;
- худшие сотрудники;
- количество выполненных работ;
- количество отклонений;
- количество замечаний.

На раннем этапе часть итоговых данных может переноситься в Excel вручную.

# Назначение основных частей
- cmd — точка входа приложения.
- app — запуск и сборка приложения.
- config — загрузка конфигурации.
- domain — основные структуры данных.
- service — основная логика приложения.
- repository — работа с PostgreSQL.
- transport/telegram — взаимодействие с Telegram.
- middleware — проверки перед обработкой сообщений.
- migrations — изменения структуры базы данных.
